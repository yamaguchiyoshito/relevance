# 付録 ── 関係型・効能型・記述軸・Entityスキーマ・共通例の全記述

[連載目次へ](README.md)

本文は一回につき2〜3個の関係型を深く扱い、一覧は本文に置かなかった。この付録は、本文が参照する一覧と仕組みをまとめたものである。付録なしでも本文は読めるが、「相似を探す」「創発が起きうる組み合わせを探す」といった操作を実際に行うときは、ここが辞書になる。

各一覧の ID（REL-／SEM-／EFF-）は本文には出てこない。本文が概念語だけで書かれているのに対し、付録は機械可読な整理を優先する。ID と定義は本連載が置いた仮の体系であり、確立した標準ではない。

## 付録A　関係型の一覧（第1回・第4〜7回）

二者の関係の型を七つの群に分ける。一組の二者に複数の型が同時に当てはまる（第1回「関係は一つではない」）。

### A-1　存在論的関係

| ID | 型 | 定義 |
| --- | --- | --- |
| REL-001 | 同一 | AとBが同じ実体である |
| REL-002 | 包含 | AがBを集合・範囲として含む |
| REL-003 | 全体・部分 | BがAの構成要素である |
| REL-004 | 上位・下位 | AがBの上位概念である |
| REL-005 | 所属 | AがBという集団・組織に属する |
| REL-006 | 実体・属性 | BがAの性質を表す |

第3回の「包含と構成」の区別は、REL-002／REL-004（種類として含む）と REL-003（部品として含む）の区別である。

### A-2　比較的関係（第4回）

| ID | 型 | 定義 |
| --- | --- | --- |
| REL-007 | 相似 | AとBに共通する構造や性質がある |
| REL-008 | 相違 | AとBの属性が異なる |
| REL-009 | 反対 | AとBが共通軸上で反対の性質を持つ |
| REL-010 | 対称 | AとBが所定の変換について対応する |
| REL-011 | 逆転 | AとBの方向・順序・役割が逆である |
| REL-012 | 双対 | AとBが相互に対応する二重の構造を持つ |
| REL-013 | 同型 | AとBの構造が対応関係の下で保存される |
| REL-014 | 矛盾 | AとBが同一条件下で同時に成立しない |
| REL-015 | 対比 | AとBを共通の観点から比較し、差異を際立たせる |

比較関係をさらに細かく分けると、次の14種になる。本文では相似・反対・類比を深く、逆転・同型・双対を短く扱った。

| 関係 | 意味 |
| --- | --- |
| 一致（同一） | AとBが完全に一致する |
| 類似（相似） | AとBの構造・性質が似ている |
| 共通（共通性） | AとBが一部の属性を共有する |
| 相違（差異） | AとBに異なる属性がある |
| 対照（対比） | 共通の比較軸で違いが際立つ |
| 対立（反対） | AとBが反対の性質や方向を持つ |
| 排他（矛盾） | AとBが同じ条件下で両立しない |
| 対応（対称） | AとBが特定の変換・基準に対して対応する |
| 反転（逆転） | AとBの順序・方向・役割が入れ替わる |
| 相補（補完） | AとBが組み合わさり不足を補う |
| 双対（双対性） | AとBが共通構造の中で役割を入れ替えて対応する |
| 同型（同型性） | AとBが構成要素の違いを超えて同じ構造を持つ |
| 類比（アナロジー） | 異なる領域のAとBに対応する関係構造がある |
| 相反（トレードオフ） | 一方を増やすと他方が減る傾向がある |

## 付録B　意味的関連性の一覧と評価軸（第7回）

意味が似ていることと、意味的に関連していることは別である。相似や反対は比較関係であり、類義・対義・連想・象徴・比喩は意味的関連性として扱う。

| --- | --- | --- | --- |

| SEM-003 | 対義 | 意味が対立する | 成功・失敗 |

## 付録C　効能型の一覧と、関係型との対応（第8回）

関係の種類とは独立した辞書として管理する。「促進」「抑制」「代替」のように関係型と効能型の双方に現れる語は、前者が対象間の作用、後者がその作用によって観測された結果を指す。

| EFF-001 | 創発 | 生成 | 新しい性質や機能が生まれる |
| EFF-002 | 相乗 | 増幅 | 組み合わせが単独効果の合計を超える |
| EFF-003 | 相殺 | 減衰 | 作用が打ち消し合う |

| EFF-008 | 不安定化 | 制御 | 状態の変動が大きくなる |
| EFF-009 | 強化 | 能力 | 能力や作用が高まる |

### 反実仮想による価値（第10回）

関係の純効果 ＝ 関係がある場合の結果 − 関係がない場合の結果。同一条件での比較は概念上の定義であり、実測には比較条件の統制が要る。純効果から関係の成立・維持にかかる費用を引いたものが、関係の正味の価値である。

## 付録E　Entityスキーマ（第11回）

本文では「カード」と呼んだものを、ここでは Entity として書く。関係の概念、具体的な関係、関係がもたらす効能、効能の発現条件を、それぞれ独立した Entity にする。

### E-1　Entityの体系

| Entity | 役割 | 本文の呼び名 |
| --- | --- | --- |
| Target | 関係を持つ対象 | 対象のカード |
| RelationCategory | 関係の上位分類（付録Aの七群） | ── |
| RelationType | 相似・反対などの関係概念 | 型カード |
| RelationInstance | 具体的な対象間の関係 | 実例カード |
| RelationProperty | 対称性・推移性・方向性など | 型カードの「形」の欄 |
| EffectCategory | 効能の上位分類（付録C-1の分類列） | ── |
| EffectType | 発見・創発・相乗などの効能概念 | 効能の型カード |
| EffectInstance | 具体的に発生した効能 | 効能の実例カード |
| RelationEffectRule | 関係から効能が生じる条件・仕組み | 規則カード |
| Evidence | 関係・効能の成立を裏付ける根拠 | 根拠の欄 |

一つの対象ペアに複数の RelationInstance を重ねられる。排他的分類ではない。

### E-2　共通属性

```yaml
Entity:
  id: string
  name: string
  name_en: string
  definition: string
  category: string
  aliases: string[]
  examples: string[]
  references: string[]
```

### E-3　RelationType の例

```yaml
RelationType:
  id: REL-007
  name: 相似
  name_en: Similarity
  category: Comparative
  definition: 異なる対象間に共通する構造または性質がある
  properties:
    symmetric: true
    transitive: false
    directional: false
  dimensions:
    comparison_basis: [形状, 構造, 機能, 意味, 振る舞い]
  conditions:
    - 比較する属性または構造を明示できる
    - 共通性を観察または記述できる
  potential_effects: [EFF-017, EFF-018, EFF-019]
```

`transitive: false` は、一般的な類似性が推移律を保証しないことを示す（第2回の家族的類似）。数学的な相似など、厳密な同値関係となるものは別の関係型として定義できる。

意味的関係には、意味の近さと構造の似方を分けて持たせる。

```yaml
RelationType:
  id: SEM-011
  name: 類比
  category: Semantic
  definition: 異なる対象間に対応する関係構造がある
  semantic_properties:
    semantic_distance: variable
    structural_similarity: high
    context_dependency: true
  potential_effects: [EFF-018, EFF-019, EFF-001]
  required_evidence:
    - 対応する構成要素
    - 保存される関係構造
    - 類比が成立する範囲
    - 類比が成立しない範囲
```

`semantic_distance` は、埋め込みなどのモデルと測定方法を固定しない限り、比較可能な数値にはならない。

### E-4　RelationInstance の例

```yaml
RelationInstance:
  id: RI-001
  subject: OBJ-001
  object: OBJ-002
  relation_type: REL-007
  context:
    comparison_basis: 構造
    description: 両者が入力・処理・検証の循環構造を持つ
  evidence:
    status: hypothesized
    sources: []
  confidence: 0.75
```

`confidence` は推定の確信度であり、客観的な確率として扱わない。算出方式と評価者を別途定義する必要がある（第11回「根拠と、仮説という状態」）。

### E-5　RelationEffectRule の例

```yaml
RelationEffectRule:
  id: RER-001
  relation_type: REL-007
  effect_type: EFF-019
  mechanism:
    description: 共通構造を抽出し、既存知識を別対象に対応づける
  preconditions:
    - 共通構造が特定されている
    - 知識の転用元が存在する
    - 転用先で成立条件が検証可能である
  limitations:
    - 表面的な類似は転用の妥当性を保証しない
  status: hypothesis
```

これにより、「AとBは相似である」という知識から、「既存知識の転用を試みる価値がある」という行動候補まで導出できる。

## 付録F　共通例の全記述 ── AIの生成 × 人間のレビュー（第11〜12回）

第11回の十三枚のカードと、第12回の四階層・五つの設計案を、付録Eの形式で書く。状態はすべて仮説で、根拠は第9回の記述である。

### F-1　対象

```yaml
Target:
  - id: OBJ-GEN
    name: AIの生成
    definition: 指示を受けてコードを生成する。速さを受け持つ
  - id: OBJ-REV
    name: 人間のレビュー
    definition: 生成されたコードを検査・承認・学習する。正しさを受け持つ
```

### F-2　関係の実例（5）

| ID | 型 | 形 | 内容 | 確定した回 |
| --- | --- | --- | --- | --- |
| RI-GR-01 | 順序（REL-029） | 有向：生成 → レビュー | 生成が先、レビューが後 | 第1回 |
| RI-GR-02 | 依存（REL-019） | 非対称：レビュー → 生成を必要とする | レビューは生成されたものがなければ始まらない。生成はレビューなしでも動く | 第2回 |
| RI-GR-03 | 補完（REL-016） | 双方向 | 目的「正しいコードを速く届ける」の中で、速さと正しさを分け持つ | 第5回 |
| RI-GR-04 | 競合（REL-018） | 双方向 | 資源「人間の時間」を、レビューと生成への指示・修正が奪い合う | 第5回 |
| RI-GR-05 | フィードバック（REL-027） | 循環 | 待ちが生成へ戻る。安定させる輪と膨らませる輪が同時に回りうる | 第6回 |

### F-3　効能の実例（4）

| ID | 効能型 | 価値 | 帰属 | 内容 |
| --- | --- | --- | --- | --- |
| EI-GR-01 | 効率化（EFF-012） | 正 | 全体 | コードを書く時間が短くなる |
| EI-GR-02 | 発見（EFF-018） | 正 | 対象（コード） | 欠陥が見つかる |
| EI-GR-03 | 制約生成（EFF-024） | 負 | 関係そのもの | レビュー待ちの滞留、手戻り |
| EI-GR-04 | 変容（EFF-004） | 混合 | 関係そのもの | 人間がAIの生成物をどれだけ信頼するかが変わり、依存の強度が変わる |

### F-4　規則（2）

```yaml
RelationEffectRule:
  - id: RER-GR-01
    relation_type: REL-016   # 補完
    effect_type: EFF-002     # 相乗
    preconditions:
      - 生成の速さ G が、レビューの処理能力 R を下回っている
    limitations:
      - G が R に近づくほど、遅延と累積で効能が見えにくくなる
    status: hypothesis
    evidence: 第9回の記述
  - id: RER-GR-02
    relation_type: REL-019   # 依存
    effect_type: EFF-024     # 制約生成（滞留）
    preconditions:
      - G が R を上回っている
    limitations:
      - 反転は遅れて現れ、流出した欠陥と失った信頼は不可逆
    status: hypothesis
    evidence: 第9回の記述
```

### F-5　四階層の記述（第12回）

| 階層 | 記述 |
| --- | --- |
| 構造 | 生成からレビューへの有向な流れと、レビューから生成へ戻る遅い流れ。非対称な依存。生成の質と量に連動して動く強度 |
| 作用 | 順序、依存、補完、競合、フィードバック。目的は正しいコードを速く届けること、資源は人間の時間 |
| 効能 | 直接には時間短縮と欠陥検出。間接には滞留と手戻りと信頼の変化。全体への符号は G と R の大小で反転する |
| 価値 | レビューがない世界、生成がない世界との差。条件つきで、費用を引き、立場によって違う |

### F-6　五つの設計案（第12回）

| # | 階層 | 案 | 手を入れる先 |
| --- | --- | --- | --- |
| 1 | 効能 | G を R 以下に保つ。生成を絞るか、R を上げる | RER-GR-01／02 の前提条件 |
| 2 | 構造 | 戻りの流れを速くする。小さく、頻繁に渡す | RI-GR-05 の遅延 |
| 3 | 作用 | 「レビュー」を検査・承認・学習の三つの関係に分けて設計する | RI-GR-03 の分業 |
| 4 | 外部性 | 滞留が後工程へ波及する分を、二者の帳簿に載せる | EI-GR-03 の帰属 |
| 5 | 価値 | レビューがなければ流出していた欠陥を推定する仕組みを置く | 反実仮想の指標 |

どの案も、OBJ-GEN と OBJ-REV そのものの性能には手を入れていない。変えているのは、二者のあいだのカードである。
